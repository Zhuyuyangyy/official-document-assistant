# 演示场景 1：公文审查（三层报告）

> 用户粘贴一份问题通知，Skill 输出三层审查报告（领导摘要 / 承办人修改清单 / 建议修订稿），并附督办事项与脱敏预览。

## 用户输入

用户在智能体对话框中粘贴以下通知正文：

```
关于开展信息登记的通知

为完善人员信息管理，请于2026-07-10前提交以下信息：联系人王老师，手机13812345678，身份证号110101199001011234。

办公室
2026-07-10
```

用户说：「帮我审查一下这份通知有没有问题。」

## 智能体调用

智能体识别意图为公文审查，调用确定性校验层脚本：

```bash
python scripts/gov_doc_review.py --mode review --format markdown --input examples/review/dirty-realistic.md
```

（实际演示时可将上述通知保存为文件，或通过 stdin 传入。）

## 评委关注点

1. **三层报告对应三个角色**：领导摘要（10 秒看结论）→ 承办人修改清单（逐条改）→ 建议修订稿（直接复制）。不是一整段文字，而是结构化分层。
2. **每条问题都有依据**：缺主送机关指向"GB/T 9704—2012 主体·主送机关"，PII 指向"《个人信息保护法》最小化原则"——不是泛泛说"格式不对"。
3. **PII 本地脱敏**：手机号 `13812345678` → `138****5678`（保留前 3 后 4），身份证号 `110101199001011234` → `110101********1234`（保留前 6 后 4）。脱敏在本地完成，不联网、不外传。
4. **风险等级强制提升**：虽然综合评分 56 分，但因为有 PII，风险等级直接判为"高"——避免"分数还行但有敏感信息"的误判。
5. **建议修订稿补了主送机关**：原文缺主送机关，修订稿自动补了"各部门："，并规范了日期格式（用占位符 `XXXX年XX月XX日` 提示用户补充）。
