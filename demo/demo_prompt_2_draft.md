# 演示场景 2：起草请示（自动自检）

> 用户用一句话提出起草需求，Skill 生成请示草稿骨架，并自动跑一遍合规自检，输出"草稿 + 信息缺口 + 自检报告"。

## 用户输入

用户在智能体对话框中输入：

```
请帮我写一份请示，主题是申请采购办公电脑，报给信息中心
```

## 智能体调用

智能体识别意图为起草，调用确定性校验层脚本：

```bash
python scripts/gov_doc_review.py --mode draft --format markdown --input examples/draft/request.txt
```

## 一、可编辑草稿

```text
关于申请采购办公电脑的请示

信息中心：

为保障采购办公电脑相关工作顺利开展，现就有关事项请示如下：

一、请示事项
拟申请采购办公电脑，用于保障日常办公和业务办理需要。

二、主要理由
当前相关工作对采购办公电脑提出了实际需求，现有条件难以充分满足后续工作开展。为提高工作效率、保障任务落实，建议予以支持。

三、拟办建议
1. 明确责任分工。
2. 按时报送进展。
3. 确保工作落实。

妥否，请批示。

发文单位
XXXX年XX月XX日
```

## 二、起草信息缺口

- 未提供主送机关，已暂用默认称谓。
- 未提供落款单位，已暂用"发文单位"。
- 未提供截止时间，已标注为"明确时间节点"。
- 未提供具体要求，已使用默认工作要求占位。

## 三、自动合规自检

| 序号 | 严重程度 | 问题 | 修改建议 |
| --- | --- | --- | --- |
| 1 | medium | 缺少落款单位 | 在成文日期上一行补充发文机关署名。 |
| 2 | high | 缺少成文日期 | 补充成文日期，用阿拉伯数字标注为"YYYY年M月D日"，月、日不编虚位。 |
| 3 | medium | 正文层级可能混用 | 正文层次序数依次用"一、""（一）""1.""（1）"，避免层级跳跃。 |
| 4 | medium | 请示可能不符合一文一事 | 请示应坚持一文一事，多个事项建议拆分或明确主次。 |

> 自检评分：62/100；风险等级：高。
```

## 评委关注点

1. **起草即自检**：草稿生成后自动跑一遍 review，输出"草稿 + 信息缺口 + 自检报告"——用户不用再手动审查一遍。这是 v0.8.0 的关键升级。
2. **信息缺口透明**：脚本明确告诉用户"你没给落款单位、没给截止时间、没给具体要求"，并用占位符（`发文单位`、`XXXX年XX月XX日`、`明确责任分工`）标注，避免模型编造未提供的事实。
3. **请示结语规范**：草稿自动加了"妥否，请批示。"，符合请示结语惯例（对照《党政机关公文处理工作条例》请示一文一事）。
4. **自检诚实**：自检报告如实指出草稿的问题——缺落款、缺日期、层级混用（草稿用了"一、"和"1."但缺"（一）"中间层）、请示一文多事（草稿的"三、拟办建议"下有 3 个并列事项，触发了"一文一事"启发式）。这些是模板骨架的固有缺陷，需要用户填入真实内容时修正。
5. **风险等级高**：因为缺成文日期（high），自检评分 62/100，风险等级"高"——脚本不会因为"这是自己生成的草稿"就手下留情，体现了确定性校验层的客观性。
